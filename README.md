## Постановка задачи

Необходимо реализовать подсистему приёма задач в системе обработки задач.  
Задачи могут поступать из различных источников, не связанных наследованием, но реализующих единый поведенческий контракт.

Каждая задача содержит минимальный набор данных:

- **id** — уникальный идентификатор задачи  
- **payload** — произвольные данные задачи  

Источники задач должны реализовывать единый контракт через метод `get_tasks()`.

## Контракт источника задач

Контракт источников описан с использованием `Protocol`.

```python
@runtime_checkable
class TaskSource(Protocol):
    def get_tasks(self) -> Iterable[Task]:
        ...
```

Любой источник задач должен реализовать метод `get_tasks()`.  
При этом **наследование не требуется**, что демонстрирует принцип **duck typing**.

---

## Модель задачи

Для описания задачи используется `dataclass`.

```python
@dataclass
class Task:
    id: int
    payload: Any
```

`dataclass` автоматически создаёт:

- `__init__`
- `__repr__`
- `__eq__`

что упрощает работу с объектами.

## Реализованные источники задач

В проекте реализованы три источника задач.

### GeneratorSource

Программно генерирует задачи.

Пример задачи:

```
Task(id=0, payload="generated_task_0")
```

### FileSource

Загружает задачи из JSON файла.

Пример структуры файла:

```json
[
  {"id": 1, "payload": "task1"},
  {"id": 2, "payload": "task2"}
]
```

### APIStubSource

Имитация внешнего API.  
Источник возвращает заранее подготовленный список задач.

## Подсистема приёма задач

Класс `TaskReceiver` реализует центральный компонент системы.

Он выполняет следующие функции:

- проверяет соответствие источника контракту
- получает задачи из источника
- возвращает список задач

Пример использования:

```python
receiver = TaskReceiver()
tasks = receiver.receive(source)
```
