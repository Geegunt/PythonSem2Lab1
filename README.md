## Описание работы

Проект является продолжением лабораторной работы №2 про платформу обработки
задач. Готовая доменная модель `Task` сохранена и переиспользуется без
переписывания: новая лабораторная добавляет пользовательскую коллекцию
`TaskQueue`, которая организует задачи в очередь и поддерживает ленивую
обработку.

Основной акцент работы сделан на:

- реализации протокола итерации;
- поддержке повторного обхода коллекции;
- создании ленивых фильтров через генераторы;
- совместимости с обычными конструкциями Python: `for`, `list`, `sum`;
- отсутствии лишних копий данных при фильтрации.

## Очередь задач `TaskQueue`

`TaskQueue` является пользовательской коллекцией задач.

Она поддерживает:

- добавление задач через `enqueue`;
- добавление нескольких задач через `extend`;
- получение первой задачи через `dequeue`;
- обход очереди через `for`;
- повторный обход одной и той же очереди;
- ленивую фильтрацию по статусу;
- ленивую фильтрацию по приоритету;
- комбинированную ленивую фильтрацию по статусу и приоритету.

Пример использования:

```python
from src.collections.task_queue import TaskQueue
from src.models.task import Task

queue = TaskQueue(
    [
        Task(id=1, description="Обработать заказ", priority=5, status="new"),
        Task(id=2, description="Отправить письмо", priority=3, status="done"),
    ]
)

for task in queue:
    print(task)

done_tasks = queue.filter_by_status("done")
high_priority_tasks = queue.filter_by_priority(5)
total_priority = sum(task.priority for task in queue)
```

## Ленивые фильтры

Фильтры реализованы как генераторные методы с использованием `yield`.

Доступные методы:

- `filter_by_status(status)` — возвращает задачи с указанным статусом;
- `filter_by_priority(priority)` — возвращает задачи с указанным приоритетом;
- `filter(status=..., priority=...)` — применяет несколько условий одновременно.

Фильтры не создают промежуточные списки. Задачи проверяются и возвращаются по
одной во время обхода результата.

## Соответствие требованиям ЛР3

В работе реализованы требования лабораторной:

- протокол итерации реализован через `__iter__`;
- повторный обход работает, потому что каждый вызов `__iter__` создаёт новый
  генератор;
- фильтры по статусу и приоритету выполняются лениво;
- генераторы используются в `__iter__`, `filter_by_status`,
  `filter_by_priority` и `filter`;
- фильтрация не создаёт лишних копий данных;
- коллекция совместима с `for`, `list` и `sum`;
- `StopIteration` обрабатывается стандартным механизмом генераторов Python.
